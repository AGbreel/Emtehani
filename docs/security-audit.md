# تدقيق أمني — منصة امتحاني (Multi-tenant SaaS)

> تاريخ التدقيق: 2026-11-06
> النطاق: `backend/Emtehani.API` + `backend/Emtehani.Infrastructure` + `frontend/src`
> المنهجية: مراجعة كود يدوية + اختبارات تكامل فعلية (`dotnet test`) + بناء الإنتاج للواجهة.
> **لا يحتوي هذا الملف على أي قيمة سرية، ولا تُطبع قيم الأسرار في السجلات.**

---

## 1. ملخص تنفيذي

| التصنيف | العدد | الحالة |
|---|---|---|
| حرجة (Critical) | 0 | لا توجد ثغرة حرجة مفتوحة معروفة |
| عالية (High) | 0 | لا توجد |
| متوسطة (Medium) | 3 | تحتاج إجراءً تشغيليًا (تدوير الأسرار، مراقبة التخزين، حدود التخزين) |
| منخفضة (Low) | 4 | تحسينات دفاعية |
| معلوماتية (Info) | 5 | قرارات تصميم موثقة |

**الخلاصة:** العزل بين المدرسين، صلاحيات المساعدين، أوضاع الشات، صلاحية الوصول للمحتوى،
والفصل المالي كلها مفروضة من الخادم ومغطاة باختبارات. المخاطر المتبقية تشغيلية
(إدارة الأسرار، النسخ الاحتياطي، حدود التخزين) وليست ثغرات منطق أعمال مفتوحة.

## 2. المصادقة والجلسات

| البند | النتيجة |
|---|---|
| تخزين كلمات المرور | PBKDF2 مع Salt (موجود مسبقًا، لم يُغيَّر) |
| JWT | التحقق من المُصدر والمستقبل والتوقيع والصلاحية؛ `ClockSkew` = 30 ثانية |
| مفتاح JWT | إلزامي خارج Development، وبطول 32 بايت على الأقل، وإلا يفشل تشغيل التطبيق |
| حد محاولات الدخول | `LoginThrottle` + سياسة `auth` = 60 طلب/دقيقة لكل IP |
| حد تخمين أكواد الدخول | سياسة `join` = 10/دقيقة لكل مستخدم (وليس لكل IP) |
| حد استعلام الهاتف | سياسة `lookup` = 12/دقيقة لكل مدرس |
| حد عام لكل API | سياسة `api` = 120/دقيقة، مع `GlobalLimiter` احتياطي |
| CORS | قائمة أصول صريحة فقط؛ HTTPS إلزامي في الإنتاج؛ لا Wildcards |
| Forwarded Headers | لا يُوثق `X-Forwarded-For` إلا بعنوان/شبكة وكيل مُعلنة صراحةً |

**ملاحظة:** تسجيل الدخول لا يعيد توكينات في عنوان URL، والتوكن يُرسل في `Authorization` فقط.

## 3. الأدوار والعزل بين المستأجرين (Tenants)

- الأدوار: `Admin`, `Teacher`, `Assistant`, `Student`.
- كل استعلام تعليمي يُقيَّد بـ `TeacherId` المحلول من الهوية، أو بـ `GroupId` بعد التحقق من ملكيته.
- المساعد لا يرى إلا المدرس المرتبط به + المجموعات المسموح بها + الصلاحيات الممنوحة.
- `TeachingAccess.RequireAsync` تفحص الصلاحية على **كل** نقطة تعليمية، وليس في الواجهة فقط.
- اختبار `TeachingModuleTests.Courses_AreIsolatedBetweenTeachers` يثبت أن مدرسًا لا يستطيع قراءة كورس مدرس آخر (404) ولا يظهر في قائمته.
- اختبار `AssistantPermissions_AreEnforcedOnEveryRequest` يثبت أن صلاحية `Courses.View` وحدها تسمح بالقراءة وترفض الكتابة، وأن منح `Courses.Manage` يفتح الكتابة.
- لوحة الإدارة محمية على مستوى التوجيه الأمامي وعلى مستوى كل Endpoint في الخادم.

## 4. حماية المحتوى التعليمي

| الضابط | التنفيذ |
|---|---|
| عدم كشف روابط التخزين | الواجهة تطلب `/api/teaching/materials/{id}/access` ثم تُشغّل `/api/teaching/media/{id}?token=...` |
| الرمز | HMAC-SHA256 قصير العمر (10 دقائق للملفات، 20 للفيديو) ومرتب بـ `materialId` + `userId` |
| إعادة التحقق عند التسليم | يُفحص الدور والاشتراك/التسجيل **وقت فتح الرابط**، لا وقت إصداره فقط |
| انتهاء الصلاحية | انتهاء تسجيل الكورس أو اشتراك المجموعة يوقف الرابط فورًا |
| مجموعات غير نشطة | `CourseAccessAsync` يرفض المجموعة إذا كانت `IsActive=false` أو انتهى `EndDateUtc` |
| العلامة المائية | طبقة اسم الطالب + كود الطالب فوق الصور والفيديو في `MyCoursesPage` |
| منع التنزيل المباشر | `controlsList="nodownload"` + منع قائمة السياق للفيديو |
| سجل الوصول | `ContentAccessLogs` يسجل `Issue` و`Open` مع المستخدم وIP |
| المواد المجانية | `IsFreePreview` فقط تتجاوز شرط التسجيل، وتبقى داخل مسار الرمز الموقّع |
| مواد خارج النطاق | يمكن تسجيل رابط خارجي، لكن الطالب لا يصل إليه إلا عبر مسار التسليم المُتحقَّق |

**حدود صريحة لا ندّعي تجاوزها:**
- لا يمكن منع تصوير الشاشة أو التسجيل الخارجي بنسبة 100%؛ الحل الحالي يرفع التكلفة ويضع علامة مائية تُنسب المحتوى للطالب.
- لا يوجد ترميز HLS/DRM؛ الفيديو يُقدَّم من رابطه الأصلي بعد التحقق. إضافة HLS تتطلب خط معالجة وسائط منفصلًا.
- الصور العامة (صورة الملف الشخصي، غلاف المدرس، مرفقات الشات، صور الإعلانات) تُخزَّن في `wwwroot/uploads` وتُخدم علنًا. **المواد التعليمية المحمية لا تُخزَّن هناك**؛ هذا يحتاج ضبطًا تشغيليًا إن أردت جعل كل المرفقات خاصة.

## 5. حوكمة الشات

- الأنواع: `TeacherGroup`, `Direct`, `AdminDirect`, `AdminGroup`, `GroupChat`.
- الأوضاع: `TeacherOnly/Everyone/Moderated` للمجموعات، و`AdminOnly/Everyone/Announcement` لمجموعة الإدارة.
- التحقق من الوضع يتم في **`POST /messages`** نفسه؛ لا يمكن تجاوزه بإرسال طلب يدوي.
- الوضع `Moderated` يجعل رسالة الطالب غير معتمدة (`IsApproved=false`) حتى موافقة المعلم/المساعد.
- الحذف ناعم (`IsDeleted`)، والتثبيت (`IsPinned`) للمشرفين فقط، والكتم (`ConversationMemberState.IsMuted` / `MutedUntilUtc`) بمدة أو دائم.
- البحث داخل المحادثة يحترم الإشراف: غير المشرفين لا يرون الرسائل غير المعتمدة.
- كل تغيير سياسة/حذف/تثبيت/اعتماد/كتم يُسجَّل في `ChatAuditLogs` مع الفاعل والوقت.
- الواجهة تعطّل الإرسال عندما `canPost=false` **والخادم يرفض الطلب أيضًا**.

## 6. الفصل المالي

- مالية المنصة: `SubscriptionPlan` → `TeacherSubscription` → `PlatformPayment` (طلب → دفع → مراجعة إدارة → تفعيل → Grace → انتهاء).
- مالية المدرس↔الطالب: `StudentPackage`/`PackageEnrollment`/`FinancialCharge`/`StudentPayment`/`FinancialAdjustment` + `DiscountCoupon`.
- لا تُجمع الإيرادات في تقرير واحد؛ `/api/teaching/finance/summary` لا يخلط اشتراك المنصة، وتقرير المنصة منفصل في `/api/admin/reports/*`.
- اعتماد الدفع يتم من الإدارة فقط، ولا يستطيع المدرس تفعيل اشتراكه بنفسه.
- اختبار `PaidPlan_StaysReadOnlyUntilAdminApprovesPayment` يثبت: طلب مدفوع → قراءة فقط → موافقة الإدارة → كتابة + ظهور الدفع في السجل.
- المبالغ تُخزَّن كأرقام عشرية مع تسجيل طريقة الدفع والمرجع، والحذف المالي يتم عبر `void` لا حذف صف.

## 7. الإعلانات والإشعارات

- الجمهور يُحدَّد في الخادم (`Platform/Teachers/Students/Group/Course/Selected`) ويُبنى منه قائمة المستلمين.
- الإعلان المجدول لا يظهر قبل `PublishAtUtc`، والمنتهي يتوقف عن الظهور بعد `ExpiresAtUtc`.
- تسليم الإشعارات مرتبط بـ `DeliveredAtUtc` لمنع التكرار.
- تفضيلات الإشعارات تُحترم في `TeachingNotify.SendAsync`.
- محتوى الإعلان يمر عبر نفس تحقق الروابط والصور، ولا يُنفَّذ HTML خام.

## 8. إدخالات ورفع الملفات

- `MaxRequestBodySize` = 8MB على مستوى Kestrel.
- رفع الصور يتحقق من الامتداد والحجم ونوع المحتوى، ويولّد اسم ملف عشوائيًا.
- لا يُسمح بمسار قابل للتنفيذ أو رفع ملفات بأسماء يدوية.
- كل النصوص تُقصّ إلى أطوال محددة عبر `TeachingText.Safe`، وتُعالج كبيانات لا كـ HTML.
- الاستعلامات كلها EF Core مع Parameters؛ لا SQL مجمَّع من مدخلات.
- CSV يُصدَّر مع BOM UTF-8 ليفتح في Excel بالعربية، ويتم تنظيف الحقول عبر `TeachingText.Csv`.

## 9. رؤوس الأمان وحدود المنصة

تم تفعيل:
- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `Referrer-Policy: no-referrer`
- `Permissions-Policy` (تعطيل الكاميرا/الميكروفون/الموقع/التقاط الشاشة)
- `Cross-Origin-Opener-Policy: same-origin`
- `Cache-Control: no-store` لكل مسارات `/api`
- HSTS + HTTPS Redirect خارج Development
- CSP للواجهة يُتحقق منها عبر `npm run verify:csp` قبل البناء.

## 10. الأسرار — قائمة التدوير الإلزامية (بدون قيم)

> **لا تحتوي هذه القائمة على أي قيمة سرية.** المطلوب تدوير كل بند أدناه ثم نقله إلى
> متغيرات بيئة/خزنة أسرار، وإزالته من الملفات المتتبعة في Git.

| # | السر | مكانه الحالي | الإجراء |
|---|---|---|---|
| 1 | `Jwt:Key` / `JWT_KEY` | `appsettings*.json` أو بيئة النشر | تدوير فوري + تخزين في Secret Store |
| 2 | `ConnectionStrings:Default` (كلمة مرور SQL) | إعدادات النشر | تدوير كلمة المرور + تحديث سلسلة الاتصال |
| 3 | `Cloudinary:ApiSecret` | إعدادات الخادم | تدوير من لوحة Cloudinary |
| 4 | `Cloudinary:ApiKey` | إعدادات الخادم | تدوير مع السر |
| 5 | كلمة مرور SMTP / App Password | إعدادات الخادم | إبطال App Password وإنشاء غيره |
| 6 | بيانات دخول Admin bootstrap | متغيرات/إعدادات النشر | تغيير كلمة المرور بعد أول دخول |
| 7 | بيانات نشر MonsterASP / MSDeploy | ملف Publish/جهاز النشر | تدوير كلمة المرور وعدم حفظها في المستودع |
| 8 | توكن Vercel (إن وُجد محليًا) | جهاز المطوّر/`.vercel` | حذفه واستخدام تكامل Git بدلًا منه |
| 9 | مفاتيح أي خدمة ذكاء اصطناعي/بريد إضافية | إعدادات الخادم | تدوير أو إبطال |

### حالة ملفات الإعداد
- `backend/Emtehani.API/appsettings.json` و`appsettings.Production.json` **موجودان**.
- `.gitignore` يستثني `appsettings.Development.json` فقط، ولا يستثني ملفي الإنتاج.
- **تنبيه أمني:** إذا كان المستودع على GitHub يحتوي على هذين الملفين، فاعتبر قيمهما مكشوفة:
  1. دوّر كل الأسرار أعلاه.
  2. أزل الملفين من التتبع (`git rm --cached`) دون حذفهما من الخادم.
  3. أضف قاعدة تجاهل لهما.
  4. اضبط القيم عبر متغيرات بيئة النشر (MonsterASP) لا عبر الملفات المتتبعة.
- **لا تُعدَّل قيم `appsettings*.json` أثناء النشر بـ MSDeploy** حتى لا تُستبدل إعدادات الإنتاج.

## 12. مخاطر متبقية وتوصيات

1. **(متوسط) حدود التخزين:** `StorageMb` و`MaxVideoMinutes` مسجلة في الخطط، لكن لا يوجد قياس فعلي لاستهلاك التخزين لكل مدرس بعد. يُنصح بمهمة مجدولة تحسب أحجام الملفات وتمنع التجاوز.
2. **(متوسط) النسخ الاحتياطي:** لا توجد نسخ احتياطي آلي موثق لـ SQL Server في المستودع؛ يجب ضبطه من لوحة الاستضافة.
3. **(متوسط) مراقبة الدخول:** `LoginThrottle` في الذاكرة؛ عند التوسع لأكثر من نسخة يجب نقله إلى مخزن مشترك (Redis).
4. **(منخفض) الصور العامة:** يمكن نقل مرفقات الشات/الإعلانات إلى تخزين خاص وتقديمها بروابط موقعة مثل المواد.
5. **(منخفض) غياب HLS/DRM:** لا يمكن ادعاء منع التسجيل؛ العلامة المائية + الرموز القصيرة هي الحد الحالي.
6. **(منخفض) فحص الأسرار الآلي:** يُنصح بإضافة `gitleaks`/`secret scanning` في CI.
7. **(منخفض) تعدد النسخ:** إشعارات الشات تعتمد Polling؛ عند الحاجة لزمن فعلي حقيقي يُضاف SignalR مع مصادقة وصلات.

## 13. قائمة تحقق ما قبل الإنتاج

- [ ] تدوير كل الأسرار في الجدول أعلاه.
- [ ] إزالة `appsettings.json` و`appsettings.Production.json` من تتبع Git إن كانا متتبعين.
- [ ] ضبط `FrontendOrigin` و`PublicApiUrl` بعنوان HTTPS واحد صريح.
- [ ] ضبط `Jwt:Key` بطول 32+ بايت من متغير بيئة.
- [ ] تعطيل `Swagger:Enabled` في الإنتاج (الافتراضي معطّل).
- [ ] ضبط `Proxy:TrustForwardedFor` + `KnownProxies` فقط إذا كان خلف وكيل معروف.
- [ ] تفعيل النسخ الاحتياطي الدوري لـ SQL Server.
- [ ] التأكد من أن `Database:BootstrapOnStartup` مناسب لخط النشر.
- [ ] التحقق من أن حجم الطلب الأقصى يناسب أكبر فيديو مسموح.
